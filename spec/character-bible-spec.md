# 人物圣经（Character Bible）Specification

## Language Guidelines

本文档类产物使用环境检测到的响应语言生成。确保文档内容遵循：

1. **语言一致性**：全文使用同一种语言
2. **写作规范**：遵循该语言的写作风格与格式规范
3. **清晰性**：内容清晰易懂

**支持语言**：中文（zh，默认）、英文（en）

---

## Overview

本规范定义了**人物圣经（characters.md）**的结构和格式要求。人物圣经为核心人物建立档案、动机、成长弧与人物关系，避免人物沦为"只有名字和外貌"的空壳，是主线设计与正文对话创作的事实依据。

**主要用途**:
- 为情节设计提供人物动机驱动依据
- 为正文对话提供人物声音（语气、用词、口头禅）基准
- 创作中人物行为失去依据时回查与修订

---

## Document Structure

使用以下模板结构生成人物圣经：

```markdown
# 人物圣经（Character Bible）

## 修订记录（维护）

## 人物总表

| 分类 | 姓名 | 一句话定位 |
|------|------|-----------|
| 主角 | | |
| 核心配角 | | |
| 反派 | | |
| 功能性角色 | | |

## <人物姓名>（每人一节）

- 姓名 / 年龄 / 外貌 / 身份 / 职业 / 性格
- **外在目标**：（想要什么）
- **内在需求**：（真正需要什么，常与外在目标矛盾）
- **最大恐惧**：
- **性格缺陷**：
- **秘密**：
- 成长经历与关键创伤/记忆
- 语言习惯与表达方式（口头禅、语气特征）
- 人物弧光：从 __ 到 __（呼应核心主题）

## 人物关系

以列表或 Mermaid 关系图呈现：亲情/友情/爱情/敌对/利益关系及内在张力。
```

**Key Elements**:
- 欲望-恐惧-缺陷三角：每个核心人物必填，驱动其一切行为
- 人物弧光：变化轨迹须与概念卡核心主题呼应
- 人物关系：含关系中的内在张力，不只写关系类型
- 修订记录：头部维护

---

## Section Guidelines

### 人物档案 Guidelines

**Important**:
- 每个核心人物必须有"欲望-恐惧-缺陷"三角
- 反派同样需要合理的动机与立场，不能只是"坏"
- 人物设定不得违反世界观规则（能力体系、社会结构等）
- 功能性角色档案从简，避免设定膨胀

**Example**:
```markdown
- **外在目标**：查清塔顶灯光自行亮起的原因
- **内在需求**：重新找回与世界和他人的联结
- **最大恐惧**：再次被唯一在意的人遗忘
- **性格缺陷**：用冷漠掩盖依赖
- **秘密**：他的失忆并非意外
```

### 人物关系 Guidelines

可用 Mermaid 图或列表；每条关系须写出**内在张力**（如"信任与提防并存"），为情节冲突服务。

## Usage Guidelines

生成人物圣经时：

1. **Step 1**: 读取 `concept.md`、`worldbuilding.md`
2. **Step 2**: 列出角色清单并分类（主角 1-2 名/核心配角/反派/功能性角色），先向用户确认增删
3. **Step 3**: 逐人建立档案、弧光，梳理人物关系
4. **Step 4**: 整合保存，经用户确认后收尾

**Important**:
- 修改已确认的人物设定时更新本文件并登记修订记录
- 同时提醒用户检查主线与分章大纲中该人物的情节是否受影响

## Best Practices

1. **动机先行**：人物的每个重大行为都应能追溯到其三角设定
2. **声音可辨**：语言习惯要具体到"遮住名字能认出是谁在说话"
3. **弧光呼应主题**：主要人物的变化轨迹与故事主题同构

### Common Pitfalls to Avoid

- 档案堆砌外貌与履历，缺少欲望-恐惧-缺陷三角
- 人物数量失控——功能性角色不必人人建档
