# 故事蓝图（Story Blueprint / Plotline）Specification

## Language Guidelines

本文档类产物使用环境检测到的响应语言生成。确保文档内容遵循：

1. **语言一致性**：全文使用同一种语言

3. **清晰性**：内容清晰易懂

**支持语言**：中文（zh，默认）、英文（en）

## Overview

本规范定义了**故事蓝图（plotline.md）**的结构和格式要求。故事蓝图确定核心冲突、主线与支线、故事结构、情节节点、结局与悬念设计，完成从"有一个创意"到"真正有一个故事"的架构转折，是分章大纲拆解的直接输入。

**主要用途**:
- 将概念、世界观、人物整合为可拆解的完整故事架构
- 为 `plan-chapters` 提供必须完整覆盖的情节节点清单
- 架构重构时的复用基准

---

## Document Structure

使用以下模板结构生成故事蓝图：

```markdown
# 故事蓝图（Story Blueprint）

## 修订记录（维护）

## 1. 核心冲突
- 外部冲突：（人物 vs 人物/环境/社会）
- 内部冲突：（对应主角"外在目标 vs 内在需求"）
- 两层冲突如何交织升级

## 2. 故事主线与支线
- 主线：主角的目标与行动路径（含关键转折点）
- 支线：每条支线注明其如何服务/反衬主线与主题

## 3. 故事结构
所选结构模型及各幕/阶段占比（如三幕式：建立 25% / 对抗 50% / 解决 25%）。

## 4. 情节节点
按结构逐节点列出，每个节点写明：
- 发生什么 / 谁参与
- 对主线与人物弧的影响

典型节点：触发事件、第一幕转折、中点反转、重大挫折、最终对决、高潮、结局。

## 5. 结局
- 核心冲突如何解决
- 人物弧光是否完成
- 主题落点与读者余韵

## 6. 悬念与期待
跨章节谜团、反转与读者期待，标注"需在 plan-chapters 中安排回收的位置"。
```

**Key Elements**:
- 双层冲突：外部与内部冲突必填且须交织升级
- 情节节点：每节点可追溯到人物动机
- 悬念标注：每项悬念注明预期回收位置，供大纲登记
- 修订记录：头部维护

---

## Section Guidelines

### 情节节点 Guidelines

**Important**:
- 情节由人物动机驱动，不设计"人物为了剧情需要而做出违背设定行为"的节点
- 主线必须完整：目标明确、阻力递增、代价可感、结局可信
- 每个节点写明参与人物与其动机来源

**Example**:
```markdown
- **中点反转**：主角发现修改代码的代价是记忆，而委托他改代码的人正是冲着他的记忆来的。
  - 对主线：目标从"弄清原理"转为"阻止对方"。
  - 对人物弧：迫使他直面"内在需求（联结）vs 外在目标（独善其身）"的矛盾。
```

### 支线 Guidelines

支线克制，宁少勿滥；每条支线须写明服务或反衬主线的具体方式。

### 故事结构 Guidelines

三幕式为默认推荐但由用户拍板；悬疑多重反转等类型需要变体时向用户说明并调整。

## Usage Guidelines

生成故事蓝图时：

1. **Step 1**: 读取 `concept.md`、`worldbuilding.md`、`characters.md`
2. **Step 2**: 与用户确认结构模型
3. **Step 3**: 依次完成冲突、主线支线、结构、节点、结局、悬念设计
4. **Step 4**: 完成一致性自检后保存，经用户确认后收尾

**Important**:
- 一致性自检：每个情节节点可追溯到某个人物动机；无节点违反世界观规则；核心冲突在结局得到回应
- 修改已确认蓝图时更新本文件并登记修订记录；若分章大纲已存在，提醒用户运行 `/asdm-plan-chapters` 重新拆解受影响部分

## Best Practices

1. **冲突可升级**：核心冲突设计成可随篇幅递进而升级的形态
2. **节点即承诺**：情节节点清单是分章大纲的覆盖契约，须完整
3. **悬念有去向**：每项悬念都标注预期回收位置

### Common Pitfalls to Avoid

- 节点只有事件没有人物动机来源
- 支线游离于主线与主题之外
