# 分章情节大纲（Chapters Outline）Specification

## Language Guidelines

本文档类产物使用环境检测到的响应语言生成。确保文档内容遵循：

1. **语言一致性**：全文使用同一种语言
2. **写作规范**：遵循该语言的写作风格与格式规范
3. **清晰性**：内容清晰易懂

**支持语言**：中文（zh，默认）、英文（en）

---

## Overview

本规范定义了**分章情节大纲（chapters.md）**的结构和格式要求。大纲将故事蓝图拆解为「卷 → 章 → 场景」三级结构，每章强制四要素（目标/冲突/转折/钩子），并登记伏笔的埋设与回收，是正文创作的直接契约。

**主要用途**:
- 为 `write-story` 提供每章的写作依据（四要素与场景安排）
- 伏笔埋设与回收的登记台账
- 调整后续章节安排时的回改基准

---

## Document Structure

使用以下模板结构生成分章大纲：

```markdown
# 小说大纲

## 修订记录（维护）

## 篇幅规划
总字数目标 / 卷数与章节数量级 / 单章目标字数。

## 第一卷：<卷名>

- 卷目标（本卷结束时故事推进到哪里）：
- 本卷核心冲突与结局：

### 第 1 章：<章名>
- 本章目标：
- 本章冲突：
- 本章转折：
- 本章钩子：
- 出场人物：
- 本章关键信息：（读者与人物各获得什么信息）
- 场景：
  1. 场景 1：<地点>——（一句话：参与人物 + 场景功能）
  2. 场景 2：...
- 预计字数：

## 伏笔登记表

| 伏笔内容 | 埋设章节 | 预计回收章节 | 回收方式 | 状态 |
|---------|---------|-------------|---------|------|
```

**Key Elements**:
- 章节四要素：目标/冲突/转折/钩子，每章缺一不可
- 场景条目：每章 2-5 个场景，一句话说明（地点、人物、功能：推进/揭示/铺垫/情绪）
- 伏笔登记表：伏笔内容、埋设章节、预计回收章节、回收方式、状态
- 修订记录：头部维护

## Section Guidelines

### 章节四要素 Guidelines

**Important**:
- 本章目标写"要让读者/故事获得什么"，不是罗列"发生了什么"
- 章与章之间靠转折与钩子咬合，不靠流水账堆叠
- 本章关键信息区分"读者知道/人物知道"，信息差是悬念来源

**Example**:
```markdown
- 本章目标：让读者确认代码与现实之间的联系不是主角的臆想
- 本章钩子：调试日志末尾出现一行不是主角写的注释——"别再往下查了"
```

### 伏笔登记表 Guidelines

- 汇总蓝图中的悬念设计逐条登记
- "只埋不收"的伏笔须在节奏检查时标记并与用户决策（删除或安排回收）
- 正文写作时按登记位置埋设与回收，状态列随 `write-story` 更新

### 节奏检查 Guidelines

通读大纲检查：冲突强度持续递进、无多章平铺直叙；信息密度不失衡（连续多章设定倾泻 / 连续多章无新信息）；高潮前低谷（重大挫折）位置合理。发现问题调整章节安排并向用户说明改动。

## Usage Guidelines

生成分章大纲时：

1. **Step 1**: 读取 `plotline.md`、`characters.md`、`worldbuilding.md`（`concept.md` 推荐）
2. **Step 2**: 与用户确认篇幅规划（总字数/卷章数量级/单章字数）
3. **Step 3**: 依次完成分卷、章节拆分（四要素）、场景拆分、伏笔登记
4. **Step 4**: 节奏检查并修正后保存，经用户确认后收尾

**Important**:
- 章节拆解必须完整覆盖蓝图的情节节点
- 大纲颗粒度到"场景一句话"即可，为正文创作保留空间
- 修改已确认大纲时更新本文件并登记修订记录；若某些章节正文已写就，提醒用户哪些已写章节可能受影响

## Output Format

分章大纲输出为：

**Format**: Markdown（层级：卷 H2 / 章 H3）

**Naming**: 固定文件名 `chapters.md`

## Best Practices

1. **目标导向**：每章四要素中"目标"是其余三要素的统帅
2. **伏笔闭环**：登记表是唯一伏笔台账，埋设与回收都在此对账
3. **留白**：场景只写一句话，细节交给正文阶段

### Common Pitfalls to Avoid

- 四要素写成"本章发生 A、B、C"的流水账
- 伏笔只埋不收，或回收位置与埋设间隔失衡

## Checklist

Before finalizing 分章大纲, check:

- [ ] 篇幅规划已经用户确认
- [ ] 每章四要素齐全，出场人物与关键信息明确
- [ ] 每章 2-5 个场景且标注功能
- [ ] 蓝图情节节点全部被章节覆盖
- [ ] 伏笔登记完整，无"只埋不收"项（或有用户决策记录）
- [ ] 节奏检查通过（冲突递进/信息密度/低谷位置）
- [ ] 修订记录区已建立，已经用户确认后保存
