# 故事状态记忆（Story State）Specification

## Language Guidelines

本文档类产物使用环境检测到的响应语言生成。确保文档内容遵循：

1. **语言一致性**：全文使用同一种语言
2. **写作规范**：遵循该语言的写作风格与格式规范
3. **清晰性**：内容清晰易懂

**支持语言**：中文（zh，默认）、英文（en）

---

## Overview

本规范定义了**故事状态记忆（story-state.md）**的结构和格式要求。它在每章写完后更新，记录人物位置、已知信息、时间线与伏笔状态，是防止长篇创作中出现"人物失忆、物品瞬移、时间冲突"的核心机制。

**主要用途**:
- 为下一章写作提供"当前时刻的世界快照"
- 维护信息差（谁知道什么——悬念的来源）
- 伏笔埋设/回收状态与 `chapters.md` 登记表对账

---

## Document Structure

使用以下模板结构生成故事状态：

```markdown
# 故事状态（Story State）

> 更新至：第 <N> 章末

## 1. 人物当前状态及位置
逐人列出：姓名 — 当前位置 — 当前处境/情绪基调

## 2. 已发生的重要事件
按时间顺序列出影响后续的关键事件（一句话/事件）。

## 3. 信息差（谁知道什么）
逐人/逐阵营列出其已掌握的关键信息；标注"仅读者知道"的信息。

## 4. 未解决的冲突
当前悬置的冲突与矛盾（对应 plotline 中的主线/支线进度）。

## 5. 伏笔状态
| 伏笔内容 | 埋设章节 | 回收章节 | 状态（已埋/已回收） |

## 6. 当前时间线
故事内当前时间点及已流逝时长。
```

**Key Elements**:
- 更新至标记：头部标注"更新至第 N 章末"，与最新章节文件对齐
- 信息差：必须区分"读者知道/人物知道"
- 伏笔状态：与 `chapters.md` 伏笔登记表保持一致
- 时间线：可交叉验证人物位置与事件先后

---

## Section Guidelines

### 人物当前状态 Guidelines

只列"截至本章末"的状态，历史状态不累积堆叠；每章更新时覆盖旧值。

### 信息差 Guidelines

**Important**:
- 信息差是悬念的来源，须逐人维护
- "仅读者知道"的信息单独标注，防止正文误让人物说出不该知道的事

**Example**:
```markdown
- 林川：知道代码可改写现实；不知道委托人的真实目的。
- 委托人：知道记忆代价的完整机制。
- 仅读者知道：林川的失忆并非意外。
```

### 伏笔状态 Guidelines

从 `chapters.md` 伏笔登记表同步：本章埋设的置"已埋"，本章回收的置"已回收"；发现登记表与实际不符时提醒用户对账。

---

## Usage Guidelines

维护故事状态时：

1. **Step 1**: 每写完一章（或按用户意见修订一章）后，依据本章正文更新各节
2. **Step 2**: 更新头部"更新至"标记
3. **Step 3**: 与 `chapters.md` 伏笔登记表对账

**Important**:
- **每章完成后必须更新本文件**——这是防止长篇失忆的核心机制
- 章节正文因用户修改而变化时，同步修订受影响的状态条目
- 本文件只记"状态"，不展开情节复述

---

## Output Format

故事状态输出为：

**Format**: Markdown（结构化小节 + 表格）
**Location**: `.asdm/workspace/<story-id>-<story-name>/story-state.md`
**Naming**: 固定文件名 `story-state.md`（单文件持续更新，不按章分文件）

---

## Best Practices

1. **快照式维护**：状态描述当前时刻，覆盖而非追加
2. **可验证**：时间线与人物位置应能直接用于检查下一章正文是否穿帮
3. **对账习惯**：伏笔状态与大纲登记表双向核对

### Common Pitfalls to Avoid

- 状态写成章节情节复述，越积越长
- 遗漏"仅读者知道"的信息导致正文泄密

Before finalizing 故事状态, check:

- [ ] 头部"更新至第 N 章末"与最新章节对齐

- [ ] 伏笔状态与 `chapters.md` 登记表一致
